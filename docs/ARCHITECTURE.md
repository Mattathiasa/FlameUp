# FlameUp — Architecture

> Flutter 3.19.6 / Dart 3.3.4 · Riverpod · go_router · Firebase
> Constraints behind the version choices: `docs/PROJECT_AUDIT.md` §2.1.

---

## 1. Shape

Feature-first. Each feature owns its own data, domain and presentation layers;
`core/` holds what every feature needs; `shared/` holds what more than one
feature reuses but nothing owns.

```
lib/
  main.dart              bootstrap: Firebase, storage, crash handler, run
  app.dart               MaterialApp.router, theme + locale wiring
  firebase_options.dart  generated by flutterfire, do not edit

  core/
    constants/   app constants, Firestore path registry
    errors/      Failure hierarchy, ErrorMapper
    result/      Result<T> = Ok | Err
    router/      go_router config, redirect guards, tab shell
    services/    Firebase bootstrap, connectivity, local store,
                 analytics, crash reporting
    theme/       design tokens -> ThemeData (Phase 2)

  features/<feature>/
    data/          repository implementations, DTOs, remote + local sources
    domain/        models, providers, pure business logic
    presentation/  screens and feature-scoped widgets

  shared/
    models/        types crossing feature boundaries
    repositories/  base classes and shared caching behaviour
    widgets/       the component library (Phase 2)

  l10n/            app_en.arb, app_am.arb  (generated -- see §7)
```

Rule of thumb: a widget may depend on `domain`, never on `data`. Repositories
are the only code that touches Firestore, Storage or Functions.

## 2. State — Riverpod

`flutter_riverpod` 2.6. No business logic in widgets; a widget reads providers
and renders.

| Provider kind | Used for |
|---|---|
| `Provider` | services and pure derivations (`isOfflineProvider`) |
| `StreamProvider` | live Firebase streams (`authUserProvider`) |
| `FutureProvider` | one-shot reads |
| `NotifierProvider` | mutable UI state with actions (`themeModeProvider`) |
| `AsyncNotifierProvider` | mutable state whose load is asynchronous |

Two providers are deliberately overridden at the root rather than lazily
constructed, because routing and theming must be correct on the *first* frame:

- `localStoreProvider` — overridden in `main()` with an already-open
  [`LocalStore`], so theme, language and the onboarding flag read synchronously.
- Everything else resolves lazily.

## 3. Errors — one currency

Nothing above the repository layer ever sees a `FirebaseException`.

```
provider error  ->  ErrorMapper.map()  ->  Failure  ->  Result.err  ->  UI copy
```

- **`Failure`** (`core/errors/failure.dart`) is a sealed hierarchy:
  `NetworkFailure`, `ServerFailure`, `AuthFailure`, `PermissionFailure`,
  `ValidationFailure`, `NotFoundFailure`, `CacheFailure`, `CancelledFailure`,
  `UnknownFailure`. Each carries a **`messageKey`** — a localisation key, never
  a provider string — plus the original cause for Crashlytics only.
- **`Failure.isRetryable`** decides in one place whether the UI offers a retry.
- **`ErrorMapper.guard`** wraps every repository call. `wrong-password` and
  `user-not-found` intentionally collapse onto the same message so the app does
  not disclose which half was wrong.
- **`Result<T>`** (`Ok | Err`) is the repository return type, so callers must
  handle the error branch instead of meeting it as an uncaught exception in
  `build()`.

`test/core/localization_test.dart` asserts every `messageKey` resolves in both
languages, so a missing translation fails the suite rather than rendering blank.

## 4. Navigation — go_router

`core/router/routes.dart` holds every path; each is annotated with the design
screen it renders, so a route traces straight to
`design/extracted/screens/<n>-<id>.html`.

**`StatefulShellRoute.indexedStack`** gives the five tabs independent
navigation stacks — leaving Explore mid-drill-down and coming back preserves the
stack. Tapping the active tab pops that branch to its root.

Full-screen routes (cook mode, finished, rate, offline) sit on the **root**
navigator so they cover the tab bar, matching the design: nine screens hide it.

### Redirect guards

```
auth status unknown           -> /splash        (never bounce a returning user)
not authenticated             -> /welcome       (unless already on a public route)
authenticated, not onboarded  -> /onboarding/skill
authenticated and onboarded   -> /home          (if on a pre-app route)
```

`AuthStatus.unknown` exists specifically so a cold start does not flash the
welcome screen before Firebase restores the persisted session. Guests are
authenticated: `AuthStatus.guest` passes every gate a full account does.

A `NavigatorObserver` leaves a Crashlytics breadcrumb per navigation — route
names only, never query values.

## 5. Data — offline-first

FlameUp is **offline-first**, not offline-tolerant: a cached value is served
immediately, every time, and freshness only decides whether a background
refresh also runs. Full detail in [`OFFLINE_MODE.md`](OFFLINE_MODE.md).

| Tier | Technology | Holds |
|---|---|---|
| Firestore persistence | built in | document reads and live listeners |
| `CacheStore` | Hive, JSON | query results, feed pages, recipe lists |
| `Outbox` | Hive, JSON | writes waiting to reach the server |
| `SharedPreferences` | scalars | theme, language, onboarding flag, session id |

Deliberately **not a local database**. The app caches documents and lists keyed
by query — a key-value shape. SQLite/Drift would add codegen, migrations and a
native dependency to buy joins nothing here performs.

### Reading

`OfflineFirst.read` implements the policy once: emit cache immediately, refresh
if stale, **keep showing cached data when a refresh fails**, and throw only
when there is nothing cached *and* nothing fetched.

Repositories emit `Cached<T>` rather than a bare `T`, carrying `origin`
(cache / network / cacheAfterFailure), `isRefreshing` and `refreshFailed`.
`AsyncValue.loading` cannot express "here is real content, and it is updating"
because its loading state has no data; `Cached` can, so screens never flash a
spinner over content the user was already reading.

### Writing — the outbox

Writes are appended to a durable queue **and applied locally first**, so the UI
is correct immediately whether or not there is a network.

Each `PendingMutation` carries an **idempotency key minted when the user acts**,
not when the request is sent. A retry, a restart mid-drain or a double tap all
carry the same key and the server refuses the second grant — this is what stops
a cook finished on a plane awarding XP twice on landing.

Mutations replay oldest-first and the drain stops at the first failure, because
"start session → step 4 → complete" applied out of order produces a session
that never ran. Backoff is exponential and capped; after 8 attempts a mutation
is dropped so a permanently rejected write cannot block the queue forever.

Every cache and outbox read is non-throwing: a corrupt entry is dropped and
reported as a miss rather than taking a screen down.

## 6. Security posture

The client is not trusted with progression. XP, level, achievement grants,
mastery and leaderboard positions are written **only** by Cloud Functions;
Firestore rules make those fields unwritable by clients. The app calls a
`RewardService` that invokes a callable function and reads back the result.

Cloud Functions cannot be deployed until the project moves to the Blaze plan
(`docs/FIREBASE_SETUP.md`). Until then the functions run in the **emulator
suite** — the client code path is identical, and the rules already reject
client-side XP writes, so nothing is faked.

No provider API key ships in the binary. The AI assistant talks to a callable
function that holds the key in Functions config.

App Check attests requests: Play Integrity / App Attest in release, debug
providers in debug builds.

## 7. Localisation

English and Amharic, generated rather than hand-written:

```
design/extracted/strings.json   206 pairs, decoded from the prototype
tool/l10n_extra.json             33 pairs the design lacked (errors, actions)
        |
        v  tool/generate_l10n.py
lib/l10n/app_en.arb  +  app_am.arb        <- never hand-edit
        |
        v  flutter gen-l10n
lib/l10n/generated/app_localizations.dart
```

The generator rejects any key that is a Dart keyword or would shadow an
`AppLocalizations` member; `continue` and `of` are renamed to `continueLabel`
and `ofWord` with their copy untouched.

**Amharic is left-to-right.** `app.dart` pins `TextDirection.ltr` so no
locale-derived default can flip the layout. One font family
(Noto Sans Ethiopic, four weights instanced from the variable font) covers both
scripts, so a mixed sentence never hops fonts mid-line.

## 8. Analytics and crash reporting

Event names are constants on `AnalyticsService`, not free strings, so the set
stays reviewable. Only the opaque uid is attached — never email or display
name, and never free text the user typed.

`CrashReporter` disables upload in debug builds. Expected conditions — offline,
a cancelled sign-in, a validation error — are not reported; everything else is.

## 9. Testing

| Level | Covers |
|---|---|
| Unit | XP, level, mastery, streak, quest and achievement rules; ingredient scaling; `Result`/`ErrorMapper` |
| Widget | recipe card, rating control, quest card, cook screen, progress |
| Integration | the brief's §63 journey, including kill-and-resume mid-cook and offline reconnect |
| Rules | Firestore and Storage rules against the emulator |

The progression maths is deliberately **pure Dart** with no Firebase imports,
so it is tested without mocks and shares its logic shape with the server
implementation.
